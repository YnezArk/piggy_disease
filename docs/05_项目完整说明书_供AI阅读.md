## 0. 一分钟速览

**音识咳** 是一个猪呼吸道疾病的声学监测与诊疗辅助决策系统。它做三件事，串成一条流水线，也可以拆开单独跑：

| 环节 | 输入 | 输出 | 方法 |
|---|---|---|---|
| 声学监测 | 长时栏舍录音（分钟~小时） | 咳嗽事件（时间戳+置信度）、小时频次、预警级别 | 端点检测 + 39 维 MFCC + CNN-BiLSTM |
| 辨病 | 1 秒音频片段 | 6 类之一 + 置信度 + Top-3 候选 | 84 维多域特征 + SSLRB 选择性集成 |
| 论治 | 病名 + 症状 + 体温 + 体重 | 证型、治则、方剂（君臣佐使+剂量）、安全校验报告 | RAG 三库 + LLM 三阶段 + 规则引擎 |

规模：Python 63 个文件 6,897 行，SQL 2 个文件 2,558 行，合计 9,455 行。
技术栈：Python 3.10+（实测 3.14）、numpy、scikit-learn、librosa、TensorFlow（仅监测模型推理）、FastAPI、Flask、PyMySQL、jieba、OpenAI 兼容客户端。

**三个模块互不 import**，只通过 `diagnosis/bridge.py` 这一层契约转换。这是整个项目最重要的架构约束。

## 1. 项目定位与边界

**解决的问题**：规模化猪场里，呼吸道疾病的早期发现依赖饲养员巡栏听诊，人不可能 24 小时守着，且判断靠经验；发现时往往已经全群发病。另一方面，即使判断出病，基层用药也缺少剂量换算和安全校验的依据。

**做什么**
- 从连续录音里自动找咳嗽、数频次、按小时给出预警
- 用 1 秒音频判断 6 类疾病状态（含"健康猪只"）
- 按中兽医思路给出证型与方剂，并用确定性规则做剂量换算与配伍禁忌拦截

**不做什么（重要，避免 AI 过度扩展）**
- 不做图像/视频识别，只做声音
- 不做临床确诊，输出是"辅助决策"，所有报告带免责声明
- 辨病不做拒答：恒输出 6 类之一，取最高概率（`diagnosis/predict.py:14`）
- 论治不追求自主开方：LLM 只拟初稿，规则引擎有否决权

## 4. 模块一：声学监测（monitor）

### 4.1 职责
把一段长录音变成"第几秒到第几秒有一声咳，置信度多少"，再聚合成小时频次和预警等级。

### 4.2 处理链（7 步，参数全部在 `monitor/config.py`）

| 步 | 做什么 | 关键参数 |
|---|---|---|
| 1 读取 | librosa 读音频，统一重采样 | `SAMPLE_RATE=44100`，单声道 |
| 2 带通 | 4 阶巴特沃斯滤除风机高频与低频机械振动 | 100–2000 Hz |
| 3 预加重 | 一阶高通补偿高频衰减 | α = 0.97 |
| 4 分帧 | 25 ms 帧长 / 10 ms 帧移 / 汉明窗 | 帧长 1102 点、帧移 441 点 |
| 5 端点检测 | 逐帧 RMS 能量，阈值自适应 | `TE = μ_E + 0.5σ_E` |
| 6 特征 | MFCC13 + Δ13 + ΔΔ13 = 39 维，填充/截断到 101 帧 | `N_MELS=24`、`N_FFT=2048` |
| 7 推理 | 每段过 CNN+BiLSTM，输出咳嗽概率 | 阈值 0.4 |

**端点检测细节**（`monitor/src/preprocess.py:54 energy_endpoint_detect`）：能量高于 TE 的连续帧构成候选段；间隔 ≤150 ms 的候选段合并（防止一声咳嗽被切成两段）；短于 0.2 s 丢弃；长于 1.5 s 从段首截断。返回 `[(start_sample, end_sample), ...]`。
自适应阈值的意义：不需要为每条录音手调阈值，安静栏舍和吵闹栏舍都能用。

### 4.3 模型结构（参数 392,514）

```
Input (101, 39, 1)
Conv2D(32, 3×3, relu) → MaxPool → Conv2D(64, 3×3, relu) → MaxPool
TimeDistributed(Flatten)
BiLSTM(64, return_sequences=True) → BiLSTM(32)
Dense(64, relu) → Dropout(0.3) → Dense(2, softmax)
```
输入固定形状是刻意的：同一套模型能吃任意时长的录音，因为切片和定长填充都在前处理里完成。

### 4.4 长音频检测（`monitor/src/inference.py:71 predict_long_audio`）
1. 先做带通+预加重，再跑端点检测拿到所有有效段；
2. 每段单独送模型，`p_cough ≥ 0.4` 记为事件；
3. 相邻事件间隔 ≤ `COOLDOWN_SEC=2.0` 的合并为一声（保留最大置信度）；
4. 返回 `{path, duration_sec, events:[{start_sec,end_sec,confidence,label}], cough_count}`。

若整段没有任何有效段（极安静的文件），退化为固定滑窗（`WINDOW_SEC=1.5`、`HOP_SEC=0.5`）。

### 4.5 监测服务（`monitor/scripts/07_monitor_service.py`，547 行，项目内最大文件）

| 类 / 方法 | 职责 |
|---|---|
| `MonitorDB` | 连接管理（带重试退避）、建表、写事件、写状态、去重表、心跳 |
| `MonitoringEngine.process_file(path)` | 去重 → 长音频检测 → 按文件 mtime 推算绝对时间 → 落库 |
| `MonitoringEngine.evaluate(now)` | 统计窗口内次数 → 更新健康基线（EMA α=0.2）→ 判预警级别 |
| `MonitoringEngine.write_status()` | 默认每 60 s 落一次状态；预警变化时立即写 |
| `MonitoringEngine.run_folder_monitor(dir, 10s)` | 轮询目录，新文件即处理 |
| `SingleInstanceLock` | 单实例锁，防止重复起服务 |

**预警逻辑**（`evaluate`）：
- `count ≥ ALERT_COUGH_PER_HOUR(10)` → `critical`（若 ≥ 2 倍阈值）或 `warning`
- 否则若 `count ≥ 1.5 × 基线` → `warning`
- 否则 `normal`

## 5. 模块二：辨病（diagnosis）

### 5.1 输入与约束
一段 **1.0 秒** 16 kHz 单声道音频。不足 1 秒补零。不做拒答，恒输出 6 类之一。

### 5.2 84 维特征（`diagnosis/features.py:68 extract_features`）
全部做**时间轴均值池化**，所以长度无关：

| 块 | 维度 | 内容 |
|---|---|---|
| mfcc | 13 | `librosa.feature.mfcc(n_mfcc=13, n_fft=2048, hop_length=512)` 的均值 |
| logfbank | 64 | 64 带 mel 谱 → `power_to_db(ref=np.max)` 的均值 |
| temporal | 3 | 平均能量、过零率、RMS |
| spectral | 4 | 谱质心、谱带宽、谱平坦度、谱滚降 |

合计 84 维，与数据库 `acoustic_feature` 表逐参数一致（`feature_dimension` 默认 84）。

### 5.3 SSLRB 选择性集成（`diagnosis/train_sslr.py`）
名字含义：Stacked Selective Learning with Random Balance。

1. **基学习器**：3 个 RBF-SVM，`C=100`，`gamma ∈ {0.1, 0.01, 0.001}`，各自包一层 StandardScaler。
2. **元特征**：3 折交叉验证的 out-of-fold 预测概率拼起来 → `3 × 6 = 18` 维（用 OOF 而不是训练集预测，避免元层过拟合）。
3. **元学习器**：3 个逻辑回归，分别在不同随机种子下做 Bootstrap 重采样 + 随机过采样（ROS）处理类别不均衡。
4. **推理**：3 个 LR 的 `predict_proba` 取平均。

产物 `models/diagnosis/sslr.joblib`（733 KB），结构 `{"svms": [(scaler, svm), ...], "lrs": [lr, ...], "label_names": [...]}`。

**类别顺序（下标即模型输出顺序，不可随意调整）**：
`["normal","influenza","prrs","mycoplasma","app","other_disease"]`
对应中文：健康猪只、猪流行性感冒、猪蓝耳病、猪支原体肺炎、猪传染性胸膜肺炎、其他疾病。

### 5.4 输出契约（`diagnosis/predict.py:65 diagnose`）

```json
{
  "label": "app",
  "disease": "猪传染性胸膜肺炎",
  "confidence": 0.6675,
  "cough_type": "干咳/湿咳（待监测板块补充）",
  "typical_symptoms": "急骤痛咳，湿咳，全身重症，高致死率",
  "top3": [
    {"label": "app", "disease": "猪传染性胸膜肺炎", "confidence": 0.6675},
    {"label": "other_disease", "disease": "其他疾病", "confidence": 0.2157},
    {"label": "prrs", "disease": "猪蓝耳病", "confidence": 0.0356}
  ]
}
```

**关键约定**：`typical_symptoms` 是"这个病的模板症状"，**只用于展示，绝不喂给论治**。论治需要的"实际症状"必须由用户手动传入（命令行 `--symptoms`，API 的 `symptoms` 字段）。这是 2026-08-16 定下的规则，理由是模板症状会把辨证引向"背答案"。

### 5.5 数据集与划分
- 六类共 540 条：normal 167、influenza 135、mycoplasma 148、app 49、prrs 28、other_disease 13
- 8:1:1 分层划分，`seed=42` → 486 训练 / 27 验证 / 27 测试（批次脚本口径 54 条独立测试）
- 二分类监测样本同样 540 条：cough 359 / non_cough 181

### 5.6 指标（口径必须写清）

| 指标 | 数值 | 口径 |
|---|---|---|
| 独立测试 Macro-F1 / 准确率 | 0.7516 / 83.3% | 54 条完全未参与训练 |
| 健康类召回 | 0.941 | 同上 |
| 5 折交叉验证 Macro-F1 | 0.726 ± 0.032 | 486 条训练样本 |
| 单 SVM 基线（同口径） | 0.761 ± 0.043 | 交叉验证上略高，但方差更大 |
| CNN 对照（logFBank） | 0.700 ± 0.061 | 同数据同划分 |
| CNN 对照（MFCC） | 0.575 ± 0.177 | 同上 |
| 单条推理耗时 | 约 0.07 s | CPU 单线程 |
| 全样本回测 | 95.37% | 含训练样本，仅反映拟合度，不作对外承诺 |

## 6. 模块三：论治（prescription）

### 6.1 四阶段（`prescription/therapy_engine.py:119 treatment_pipeline`）

| 阶段 | 函数 | 做什么 | 温度 |
|---|---|---|---|
| 0 查询改写 | `query_rewrite()` | 把"病名+症状+体温+严重度"改写成三条检索指令（`syndrome_query`/`classic_query`/`temp_range`） | 0.0 |
| 1 辨证 | `syndrome_stage()` | 全量辨证库 + 典籍 Top-5 + SQL 精确命中 + 规则交叉验证 → 证型/治则/依据/疾病冲突检查 | 0.0 |
| 2 组方 | `formula_stage()` | 全量论治库 + 典籍 Top-5 → 方名/君臣佐使/剂量/用法/疗程 | 0.5 |
| 3 校验 | `verify_stage()` | 纯规则：剂量换算 + 禁忌 + 剂量区间 | 无 LLM |

**阶段 2 温度 0.5 的后果**：同一输入多次运行，证型与基础方可能不同。这是特性不是 bug，已在说明书里注明。别在测试里断言固定方名。

**`FULL_KB` 开关**（`therapy_engine.py:23`）：为 `True` 时辨证库 11 条与论治库 14 条全量塞进 prompt（总共约 3.5k token），语义匹配交给大模型；典籍库因为太大仍只取 Top-5。置 `False` 可退回全检索模式。

### 6.2 三库结构与检索

| 库 | 文件 | 条数 | 字段 |
|---|---|---|---|
| 辨证库 | `data/knowledge/kg/symptom_disease.csv` | 11 | temperature_min/max, cough_type, excretion, other_signs, syndrome, disease, evidence |
| 论治库 | `data/knowledge/kg/disease_formula.csv` | 14 | disease, base_formula, herbs, add_rule, usage, course, contraindication, reference |
| 典籍库 | `data/knowledge/rag/classics/*.txt` | 230 片段 | 中兽医学_三期辨证.txt、猪呼吸道疾病诊疗规范.txt |

**检索实现**（`rag_retrieve.py`）：不引入向量数据库。jieba 分词 → 每个词取 MD5 前 8 位 → 映射到 512 维稀疏向量 → L2 归一化 → 余弦相似度排序。理由写在文件头：ChromaDB 的 hnswlib 在 Python 3.14 上查询会卡死，而语料只有 253 片段，内存检索毫秒级足够。
接口 `retrieve(name, query, k)` 与 `get_all(name)` 与 ChromaDB 版兼容，将来可直接替换。

**确定性检索**（`kb_lookup.py`）：
- `extract_sign_kw(text)`：从自由文本里抽体征词（高热、湿咳、痰多……）
- `sql_syndrome_lookup(temp, keywords, extra_kw)`：按体温区间 + 关键词查 `syndrome_mapping`，返回带权重的候选证候
- `rule_cross_check(disease, temp, keyword)`：把"全部命中规则"与上游辨病结果比对，标出矛盾

### 6.3 Prompt 输出契约
三套系统提示词在 `prompts.py`，强制 LLM 返回 JSON：

- 阶段 0：`{syndrome_query, classic_query, temp_range}`
- 阶段 1：`{stage(前期/中期/后期), syndrome, principle, evidence[], references[], disease_conflict{upstream_disease, evidence_disease, conflict, reason}}`
- 阶段 2：`{base_formula, herbs[{name, dosage_g, role(君/臣/佐/使)}], add_notes[], preparation, course, contraindications[], references[]}`

`llm_client.extract_json()` 负责从可能带 ```json 围栏的文本里抠出 JSON。

### 6.4 安全校验（`safety.py`，纯规则，不经 LLM）

**剂量换算**
```
新剂量 = 基础剂量 × 体重系数 × 病情系数
体重系数：<25kg 0.7 ｜ 25–60kg 1.0 ｜ 60–100kg 1.3 ｜ >100kg 1.5
病情系数：轻度 0.8 ｜ 中度 1.0 ｜ 重度 1.2
```
只对**灌服/煎汤类**换算；拌料/混饲类按整方给药，不逐味折算（`therapy_engine.py:102 verify_stage`）。

**四类判定**

| 规则 | 判定 | 处理 |
|---|---|---|
| 十八反 / 十九畏配伍 | 两味药在 `herb_contraindication` 表命中 | **errors，硬拦截**，整张方作废 |
| 单味剂量 > 上限 × 8 | 防 LLM 幻觉（兽药整方可达人用上限 5–6 倍，故阈值取 8） | **errors，硬拦截** |
| 剂量超出人用参考区间 | `dosage_min/max` 从 `herb` 表读 | warnings，标黄提醒 |
| 孕猪慎用 / 药材未入库 | `caution` 字段含"孕"；或药材名不在 `herb` 表 | warnings |

返回：`{safe, errors[], warnings[], score}`，`score = max(0, 1 − 0.3×错误数 − 0.05×提示数)`。

规则数据来自 MySQL：`herb`（79 味，含剂量区间与注意事项）、`herb_contraindication`（配伍禁忌，双向入表）。**校验前会一次性把两张表载入内存**（`_load()`），后续零查库。

### 6.5 批量审计（`safety_verify.py`）
`python prescription/safety_verify.py audit` 对 237 张历史问题处方一次性复核，输出分类统计与未拦截明细。

实测：237 张中拦截 234 张（98.7%）；规则覆盖范围内 234/234 = 100%；覆盖外 0/3。
未拦截的 3 张是**已知缺口**，不是漏检：十九畏未入库（#72）、药材未入库无法核对剂量（#91）、孕猪仅软提示（#32）。

### 6.6 接口（FastAPI :8000）

|---|---|---|
| POST | `/api/diagnosis` | 传疾病+症状+体温+体重+严重度，走完整论治 |

## 7. 契约层：`diagnosis/bridge.py`

全项目只有 60 行，但它是解耦的关键。

**三条约定**
1. 辨病只产 JSON `{label, disease, confidence, cough_type, typical_symptoms, top3}`；
2. 论治只认 `{disease, symptoms, temp, weight, severity, pig_extra}`；
3. 本模块是唯一转换点，两端互不 import（论治侧用惰性 import 打破循环）。

**字段映射**

| 辨病输出 | 论治输入 | 说明 |
|---|---|---|
| `disease`（中文病名） | `disease` | 过别名归一（"支原体肺炎"→"猪支原体肺炎"） |
| — | `symptoms` | **只来自手动输入**；未提供则空串，论治按"缺实际症状"低置信度处理 |
| — | `temp`, `weight`, `severity`, `pig_extra` | 调用方给，默认 39.0 / 70.0 / 中度 / "" |
| `label` | 不进论治 | 落库时写 `model_label` |
| `confidence` | 不进论治 | 落库 + 论治纠错参考 |
| `typical_symptoms` | **不进论治** | 仅显示 |
| `top3` | 不进论治 | 落库 |

`call_therapy()` 负责按契约调用 `treatment_pipeline`，惰性 import，避免模块间硬依赖。

## 8. 端到端时序（一次完整诊疗）

```
① 用户给一段音频 cough.wav + 体温 40.1℃ + 症状"湿咳、痰多"
② prescription/pipeline.py 调 diagnosis.predict.diagnose(wav)
   → {"label":"app","disease":"猪传染性胸膜肺炎","confidence":0.6675,...}
③ bridge.build_therapy_input(dx, temp_c=40.1, symptoms="湿咳、痰多")
   → therapy={"disease":"猪传染性胸膜肺炎","symptoms":"湿咳、痰多","temp":40.1,"weight":70.0,...}
   → meta={"label":"app","confidence":0.6675,"top3":[...]}
④ therapy_engine.treatment_pipeline(**therapy)
   ④.0 query_rewrite → {"syndrome_query":"湿咳 痰多", ...}
   ④.1 syndrome_stage → 证型"疫热壅肺"，治则"清热解毒，宣肺平喘，化痰开窍"
   ④.2 formula_stage  → 基础方"麻杏石甘汤"，4 味（石膏24 君/麻黄9 臣/杏仁9 佐/甘草6 使）
   ④.3 verify_stage   → safe=True，warnings=["麻黄: 孕猪慎用","麻黄: 11.7g 超出人用参考区间 3.0-10.0g"]
⑤ 组装报告 + 免责声明；API 场景下落 diagnosis_record / prescription_record
```
实测耗时 37–43 秒，其中绝大部分是三次 LLM 调用；辨病单条只需 0.07 秒，校验 0.09 秒。

## 12. 已知限制与缺口

1. **辨病只有 6 类**，且 `other_disease` 仅 13 条。猪肺疫、混合感染等无标注类别未覆盖，当前不做拒答，会强行归到 6 类之一。
2. **辨病准确率 83.3%** 是 54 条独立测试的结果，样本量小，置信区间宽；论文/答辩引用时应说明口径。
3. **SSLRB 在 5 折交叉验证上不如单 SVM**（0.726 vs 0.761），其优势体现在独立测试与方差更小；不要宣称"全面优于基线"。
4. **安全规则有三个已知缺口**：十九畏未入库、药材未入库时无法校验剂量、孕猪仅软提示不硬拦截。批量审计如实报告，不要掩盖。
5. **论治强依赖 LLM 可用性**：网络或密钥不可用时阶段 0–2 无法完成；阶段 3 校验本身不依赖 LLM。
6. **阶段 2 非确定性**：温度 0.5，同一输入可能给出不同证型/方剂。
7. **监测模块在本机不能直接跑推理**（缺 TensorFlow），但训练脚本、评估结果与模型文件齐全。
8. 典籍库只有 230 片段，RAG 的覆盖面有限，检索质量受语料规模限制。

## 13. 改动指引（AI 最需要的一节）

| 想改什么 | 动哪里 | 注意 |
|---|---|---|
| 加一类疾病 | `diagnosis/predict.py` 的 `LABEL_NAMES`/`DISEASE_NAMES`/`TYPICAL_SYMPTOMS`；重训 `train_sslr.py`；补 `data/raw/six_class/<新类>/` | 类别顺序变化会让旧模型失效，必须整链重训；同步改 `syndrome_mapping` |
| 调咳嗽判定灵敏度 | `monitor/config.py` 的 `CONFIDENCE_THRESHOLD` | 调低→漏检少误报多，可用 `results/monitor/paper_figures/fig6` 的阈值曲线论证 |
| 改预警阈值 | `monitor/config.py` 的 `ALERT_COUGH_PER_HOUR` / `ALERT_RATIO_BASELINE` | 与 `MonitoringEngine.evaluate` 的两级判定绑定 |
| 加安全规则 | `safety.py:59 safety_check` + `herb_contraindication` 表 | 硬拦截返回 errors，软提示返回 warnings，别混用 |
| 换 LLM 或模型名 | `.env` 的 `DASHSCOPE_MODEL`/`BASE_URL` | 三套 prompt 依赖 JSON 输出，换模型后要验证 `extract_json` 仍能解析 |
| 换检索方案 | `rag_retrieve.py` | `retrieve/get_all` 接口保持兼容即可平替 |
| 加知识 | `data/knowledge/kg/*.csv` 或 `classics/*.txt` | CSV 表头不可改，`rag_retrieve._load()` 按列名取值 |
| 改契约字段 | `bridge.py` 的 `THERAPY_FIELDS` + 两端签名 | 三处必须同时改，否则契约断裂 |

**硬约束（改代码前必须知道）**
- 三个模块之间**不准互相 import**，只走 `bridge.py`。
- 辨病的 `typical_symptoms` **永远不进论治**。
- 指标口径不能混：文件级（92.59%）、片段级（96.61%）、独立测试（83.3%/0.7516）、全量回测（98.15%）是四个不同东西。
- `.env` 与任何密钥不得打印、不得提交。
- 数据库表结构以 `data/sql/pig_diag_v2.sql` 为准，改了要重导。
