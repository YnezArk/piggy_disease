# 03 辨病与论治（`diagnosis/` + `prescription/`）

> 辨病回答“是什么病”，论治回答“是什么证、开什么方”。两者通过 `diagnosis/bridge.py` 的 JSON 契约解耦。

---

# 第一部分：辨病模块

## 1. 任务与数据

- 输入：1 秒咳嗽音频；
- 输出：6 类之一 + 置信度 + Top3：`normal / influenza / prrs / mycoplasma / app / other_disease`；
- 数据：540 条，类别 167 / 135 / 28 / 148 / 49 / 13；
- 划分：8:1:1 分层（seed=42）→ train 432 / val 54 / test 54；
- 5 折交叉验证在 train+val 486 条上做。

## 2. 84 维特征

| 特征 | 维度 | 说明 |
|---|---:|---|
| MFCC | 13 | 帧均值，谱包络/音色 |
| logFBank | 64 | 对数梅尔滤波器组能量，保留更细频带分布 |
| 时域 | 3 | 短时能量、过零率、RMS |
| 频域 | 4 | 频谱质心、带宽、平坦度、滚降 |
| **合计** | **84** | 每样本一行 |

参数：`sr=16000`、`duration=1.0 s`、`n_fft=2048`、`hop=512`、均值池化。  
扩展口径 142 维（MFCC+Δ+Δ² 的均值/标准差 + logFBank 64）只用于早期消融，主模型仍是 84 维。

## 3. SSLRB 主方案

**SSLRB = SVM-Stacking + LR-Bagging（含 ROS）**。

```text
84 维特征
 ├─ 第一层：3 个 RBF-SVM，C=100，γ∈{0.1, 0.01, 0.001}
 │    3 折分层 OOF → 每个样本 3×6=18 维元特征
 └─ 第二层：3 个逻辑回归（max_iter=2000）
      每个在 Bootstrap + ROS 后的元特征上训练
      → 3 个概率平均 → 最终 6 类概率
```

- 参数量 **81,906**，模型文件约 **733 KB**；
- 预热后单条推理约 **0.07 s**；
- 训练分钟级，适合小样本快速迭代。

**为什么不用端到端 CNN**：每类只有 13–49 条，CNN 容易过拟合；84 维特征已含判别信息，集成学习更稳、更可解释。已做同数据同 5 折对照：

| 模型 | 5 折 Macro-F1 |
|---|---:|
| CNN-BiLSTM（logFBank 输入） | 0.700 ± 0.061 |
| CNN-BiLSTM（MFCC 输入） | 0.575 ± 0.177 |
| SSLRB | **0.726 ± 0.032** |
| SVM 基线 | **0.761 ± 0.043** |

结论口径：**当前 540 条、最少类 13 条的数据条件下，CNN 不占优**；不是“CNN 不行”。

## 4. 评估结果

| 口径 | SSLRB | SVM 基线 |
|---|---:|---:|
| 5 折 CV（486 条） | **0.726±0.032** | **0.761±0.043** |
| 独立测试（54 条） | Macro-F1 **0.7516**；Acc **0.833**；健康召回 **0.941** | Macro-F1 **0.6266**；Acc **0.833**；other_disease 召回 0 |
| 全样本回测（540 条，in-sample） | Acc **95.37%**（515/540） | — |

> 5 折上 SVM 更高，但独立测试 Macro-F1 SSLRB 明显更高（0.7516 vs 0.6266）：54 条测试集里 other_disease 只有 1 条，SVM 完全漏掉，Macro-F1 被这一类的 0 拉低。汇报时两个都写，不能只说“SSLRB 全面最优”。

### 特征/组件消融（Macro-F1）

| 方案 | SSLRB |
|---|---:|
| 全 84 维 | 0.7261 ± 0.0320 |
| 仅 MFCC 13 | 0.6811 ± 0.0390 |
| 仅 logFBank 64 | 0.6923 ± 0.0344 |
| 仅时域 3 | 0.3909 ± 0.0613 |

## 5. 推理与桥接

```python
# diagnosis/predict.py
diagnose(wav_path) → {
  "label": "mycoplasma",
  "disease": "猪支原体肺炎",
  "confidence": 0.83,
  "typical_symptoms": "……",   # 仅展示，不输入论治
  "top3": [...]
}
```

- 恒输出 6 类之一，不拒答；置信度供论治层纠错参考；
- `bridge.build_therapy_input()` 只转换契约；**论治的 `symptoms` 只来自手动输入**，缺省空串，不用典型症状兜底；
- 疾病名经 `disease` 表别名归一（蓝耳病 ≡ 猪繁殖与呼吸综合征）。

# 第二部分：论治模块

## 6. 四阶段流水线

```text
辨病结果 + 症状 + 体温/体重/严重度
 → 阶段0 查询改写（LLM，temperature=0）
 → 阶段1 辨证 Agent（全量辨证库 11 条 + 典籍 Top5 + SQL 精确命中；temperature=0）
 → 阶段2 组方 Agent（全量论治库 14 首 + 典籍 Top5；temperature=0.5）
 → 阶段3 校验 Agent（规则引擎，非 LLM）
 → 证型/治则/方剂/剂量/用法/禁忌/出处
```

- `FULL_KB=True`：小库全量注入，让 LLM 做语义匹配；典籍库 230 段仍用向量 Top5；
- 查询改写失败自动回退原始拼接；
- 检索片段必须带 `【来源：…】`；无命中时标注“缺检索依据”，不编造出处。

## 7. 三库与数据库

| 知识源 | 规模 | 用途 |
|---|---:|---|
| `data/knowledge/kg/symptom_disease.csv` | 11 条 | 体温/咳喘/排泄物/体征 → 证候 |
| `data/knowledge/kg/disease_formula.csv` | 14 首 | 证候/疾病 → 方剂、剂量、加减、禁忌 |
| `data/knowledge/rag/classics/*.txt` | 230 段 | 中兽医学、猪呼吸道诊疗规范 |

MySQL `pig_diag_v2` 是事实权威源：辨证规则 11 条、方剂表 20 首（RAG CSV 只取其中 14 首）、药材 79 味、配伍禁忌 8 条、证候 8 条。RAG 是 MySQL/CSV 的投影，进程启动时建索引（约 0.8 s，查询毫秒级）。

## 8. 辨病纠错（双重交叉验证）

1. **规则交叉验证（确定性）**：`kb_lookup.rule_cross_check()` 用体温 + 体征词查全部命中规则，与上游病名做别名归一比较；
   - 只有**没有任何规则支持上游病名**才 `conflict=true`；
   - 有同病规则时弱化为“多病可能”，避免误报。
2. **LLM 独立判断**：辨证 Agent 输出 `disease_conflict`，按症状独立给出证据指向疾病。

典型场景：上游错判“支原体肺炎”，但症状是 40.5℃ + 干咳 + 全群爆发 → 规则与 LLM 都指向流感方向，辨证“邪袭肺卫”，不被上游锚定。

## 9. 安全校验（规则引擎）

| 规则 | 处理 |
|---|---|
| 配伍禁忌（已入库 8 条，十八反） | **硬拦截** |
| 剂量 > 药材上限 × 8 | **硬拦截**（防幻觉） |
| 剂量超出人用参考区间 | 软提示 |
| 孕猪慎用药材 | 软提示（不硬拦截） |
| 十九畏 | **未入库，当前不校验** |
| 未入库药材 | 当前不校验 |

- 剂量换算：`基础剂量 × 体重系数 × 病情系数`；
  - 体重：<25 kg 0.7、25–60 kg 1.0、60–100 kg 1.3、>100 kg 1.5；
  - 病情：轻度 0.8、中度 1.0、重度 1.2；
  - **仅灌服/煎汤类换算**，拌料类按整方剂量校验。
- 评分：`max(0, 1 − 0.3×errors − 0.05×warnings)`。

**批量审计**：237 张问题处方（140 张配伍 + 94 张剂量 + 3 张覆盖外），拦截 234 张 = **98.7%**；覆盖内 234/234；3 张未覆盖即上表的十九畏、未入库药材、孕猪软规则。证据：`results/prescription/安全审计_237张.xlsx`。

## 10. 接口与集成

| 入口 | 说明 |
|---|---|
| `prescription/interactive_demo.py` | 终端交互，流式输出 |
| `prescription/pipeline.py <wav>` | 辨病 → 桥接 → 论治全链路 |
| `POST /api/diagnosis` | 只论治（疾病 + 症状 + 体温/体重） |
| `POST /api/diagnose-audio` | 上传音频，全链路 + 落库 |
| `GET /api/health` | 健康检查 |

API 返回：`code`、`trace_id`、`syndrome`、`prescription`、`verification`、`disclaimer`。  
落库：`diagnosis_record` + `prescription_record`；`trace_id` 格式 `RX-<id>`。

## 11. 功能验证

`tests/test_manual.py` 定义 6 个标准案例：

| 案例 | 输入 | 预期 |
|---|---|---|
| A | 支原体肺炎，湿咳痰多，39.2℃ | 疫热壅肺 |
| B | 猪流感，干咳高热，40.5℃ | 邪袭肺卫 |
| C | 猪肺疫，呼吸困难/颈肿，40.8℃ | 疫热壅肺 |
| D | 混合感染，病程长，38.5℃ | 气阴两伤 |
| E | 上游错判支原体，实际流感症状 | 邪袭肺卫 + 检出冲突 |
| F | 上游“猪蓝耳病”（别名），耳尖发紫 | 疫热壅肺 + 不误报冲突 |

最近一次完整运行 6/6 通过（需要 MySQL + 可用 Qwen 网关）。RAG 自测 6 条中 5 条通过；“高热 40.5 干咳 突发 群发”Top1 命中“风热犯肺（猪流行性感冒）”而非测试期望的“邪袭肺卫”，属检索排序/证候命名差异，后续可通过权重与同义词调整。

## 12. 局限

- 知识库覆盖有限：复杂病例、混合感染不足；
- 安全规则有 3 个已知缺口；
- LLM 依赖外部网关，模型版本/配额会影响演示；
- 尚无疗效反馈闭环；
- 数据库方剂 20 首、RAG CSV 14 首，口径需统一（当前组方 Agent 用 CSV 14 首）。
