# 处方论治引擎说明文档

> **版本**：1.0（release 交付版）
> **代码**：`therapy.py`（论治引擎）+ `api.py`（API 入口）+ `diagnose.py`（辨病）
> **基座模型**：千问（Qwen，OpenAI 兼容网关，阿里云百炼）
> **数据库**：pig_diag_v2（MySQL，26 表）

---

## 一、引擎定位与流水线

论治引擎输入**辨病结果（label）+ 实际症状**，输出**辨证 → 组方 → 安全校验**完整方案。
四阶段流水线：

```
输入（辨病 label + 症状 + 体温 + 体重 + 严重度）
  │
  ├─ [阶段0] 查询改写（LLM）   口语输入 → 标准检索词（失败回退原始输入）
  │
  ├─ [阶段1] 双路检索 + 知识注入
  │     ├─ RAG 向量检索：辨证库 CSV 全量注入(FULL_KB) + 典籍 Top5
  │     ├─ SQL 精确检索：syndrome_mapping 体温区间 + 关键词 OR 匹配
  │     └─ 规则交叉验证：命中规则映射疾病 vs 上游辨病（别名归一）
  │
  ├─ [阶段2] 辨证Agent（LLM）  证型/治则/依据/辨病纠错（温度 0.0）
  │
  ├─ [阶段3] 组方Agent（LLM）  基础方 + 药材 + 加减化裁（温度 0.5）
  │
  └─ [阶段4] 校验Agent（规则引擎，非 LLM）剂量区间/十八反/孕猪禁忌 → 通过/拦截
```

## 二、如何使用千问模型生成处方

### 2.1 调用方式

千问通过 **OpenAI 兼容网关**调用（阿里云百炼），一个 `call_qwen` 统一出口：

```python
# therapy.py
def call_qwen(system_prompt, user_content, temperature=0.3):
    resp = get_client().chat.completions.create(
        model=LLM_MODEL,                      # 默认 qwen-plus（.env 可换）
        messages=[{"role": "system", "content": system_prompt},
                  {"role": "user", "content": user_content}],
        temperature=temperature)
    return resp.choices[0].message.content
```

配置（`.env`）：

```
DASHSCOPE_API_KEY=sk-xxx          # 必填
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL=qwen-plus
```

### 2.2 完整调用示例

```python
from therapy import treatment_pipeline

result = treatment_pipeline(
    disease="app",                    # 辨病 label（内部查 DB 转中文名）
    symptoms="急骤痛咳、湿咳、高热、便秘",
    temp=41.5, weight=80, severity="重度")

# result = {
#   'syndrome':     {'stage': '中期', 'syndrome': '疫热壅肺', 'principle': '清热化痰，宣肺平喘',
#                    'evidence': [...], 'references': [...], 'disease_conflict': {...},
#                    'rule_cross_check': {...}},
#   'prescription': {'base_formula': '麻杏石甘汤加减', 'herbs': [{name, dosage_g, role}...],
#                    'add_notes': [...], 'preparation': ..., 'course': ...,
#                    'contraindications': [...], 'references': [...]},
#   'verification': {'safe': True/False, 'errors': [], 'warnings': [], 'score': 0.95}
# }
```

API 形式：`POST /api/diagnosis`（论治单独）或 `POST /api/diagnose-audio`（辨病+论治全链路）。

### 2.3 温度策略（确定性 vs 灵活性）

| 阶段 | 温度 | 理由 |
|------|------|------|
| 查询改写 | 0.0 | 检索词需要稳定，避免漂移导致检索失效 |
| 辨证 | 0.0 | 同一体征必须得到一致证型（实测 0.2 会随机漂移） |
| 组方 | 0.5 | 允许合理的个性化加减变化，但剂量/配伍由校验兜底 |

## 三、Prompt 设计 / 上下文工程说明

### 3.1 三套系统提示词

**① 查询改写（QR_SYSTEM）**——把口语化描述规范成库内检索词：

```
你是兽医临床数据检索助手。把用户的口语化临床描述改写成适合知识库检索的标准查询词。
知识库字段风格：咳喘(湿咳/干咳/阵咳/连咳/呼吸粗/痰多/喘促/张口呼吸)、
排泄物(正常/便秘/稀溏/水样便)、其他体征(精神差/食欲下降/突发/群发/病程长/颈部肿胀)
输出严格JSON：{"syndrome_query": "体征关键词", "classic_query": "典籍检索词", "temp_range": "38.5-40"}
```

**② 辨证（SX_SYSTEM）**——核心辨证逻辑，含 7 条硬约束：

```
角色：资深中兽医辨证专家（猪呼吸道疾病三期辨证：前期邪袭肺卫→中期疫热壅肺→后期气阴两伤）
上下文注入：{sym_docs} 辨证库全量规则 + {med_docs} 典籍 Top5（均带【来源】标签）
硬约束：
  1. 上游辨病结果只是参考，可能不准确——以临床症状体征和检索证据为准
  2. 同病异证：证候由体征决定，不迎合辨病结果
  3. 症状与辨病矛盾时按症状判定，并在 disease_conflict 明确指出
  4. 主症优先：咳嗽类型/体温/呼吸定证；精神/食欲/排泄物为兼症，不得因单一兼症推翻主症
  5. 特异体征优先：犬坐/张口呼吸/口鼻血性泡沫 = 肺气壅闭重症（疫热壅肺），权重高于"突发高热"
  6. 检索为空必须注明"缺检索依据"，严禁虚构出处
  7. SQL 命中仅为候选参考，最终以全量规则+特异体征核对
输出JSON：{stage, syndrome, principle, evidence[], references[], disease_conflict{...}}
```

**③ 组方（RX_SYSTEM）**——生成处方：

```
角色：中兽药师、方剂学专家
上下文注入：{formula_docs} 论治库全量方剂 + {med_docs} 典籍 Top5
规则：必须基于检索片段组方、不可虚构；检索为空注明"缺检索依据"；
     结合猪只参数（体重/月龄/严重度）加减化裁；剂量给具体克数（换算由校验环节完成）
输出JSON：{base_formula, herbs[{name, dosage_g, role}], add_notes[], preparation, course,
          contraindications[], references[]}
```

### 3.2 上下文注入分层策略（上下文工程核心）

| 数据源 | 规模 | 注入方式 | 理由 |
|--------|------|---------|------|
| 辨证库（syndrome_mapping） | 11 条 | **全量注入**（FULL_KB=True） | 仅 ~4k token；LLM 语义匹配（"老咳"≈"连咳"）远强于弱向量检索，消除漏检 |
| 论治库（formula） | 20 条 | **全量注入** | 同上，LLM 自选最匹配方剂 |
| 中医典籍 | 212+ 段 | **向量检索 Top5** | 230 段全量 ~15k+ token 且冗余多，保持检索 |
| SQL 精确命中 | 0-N 条 | 附加注入 | 体温区间 + 关键词精确匹配，与向量检索互补 |
| 规则交叉验证 | 1 段 | 附加注入 | 确定性结论供 LLM 参考 |

> 所有注入片段带 `【来源：X】` 标签 → LLM 输出引用时沿用 → 引用可溯源、防幻觉。

### 3.3 防幻觉与安全设计

1. **引用强制溯源**：检索片段带来源，提示词要求引用必须取自检索片段；检索为空 → 输出"缺检索依据"并低置信度标记
2. **辨病纠错（双重交叉验证）**：
   - 确定性规则验证（非 LLM）：SQL 命中规则映射疾病 vs 上游辨病，别名归一比较（猪蓝耳病≡猪繁殖与呼吸综合征），`conflict=true` 仅当**无任何**规则与上游同病
   - LLM 独立判断：`disease_conflict` 按症状独立判定证据指向疾病
3. **校验不依赖 LLM**（safety_check 规则引擎）：剂量超区间 8 倍硬拦截（防幻觉剂量）、十八反/十九畏查表、孕猪禁忌——安全由确定性规则保证

### 3.4 提示词中的失败兜底

- 查询改写失败 → 回退原始输入拼接检索词
- SQL 检索异常 → 跳过，不影响主流程
- LLM 输出缺 disease_conflict → 代码兜底填充默认值
- 规则库无命中 → cross_check 返回 `checked=False`，不误报

## 四、知识库结构（pig_diag_v2，26 张表）

### 4.1 表清单与数据量

| 分组 | 表 | 行数 | 职责 |
|------|----|------|------|
| **知识底座** | `disease` | 8 | 疾病字典：label/别名/病原/流行病学/**典型症状** |
| | `syndrome` | 8 | 证候字典：三期分期 + 治则治法 |
| | `syndrome_mapping` | 11 | **辨证库**：多维体征 → 证候规则（体温区间/咳喘/排泄物/其他体征/权重） |
| | `herb` | 79 | **药材库**：性味归经 + 安全剂量区间 + 孕猪禁忌 |
| | `formula` | 20 | **方剂库**：方剂名/主治证候/用法/疗程 |
| | `formula_herb` | 126 | 方剂-药材组成（剂量/君臣佐使/顺序） |
| | `add_rule` | 11 | 随症加减规则（痰多加桔梗…） |
| | `herb_contraindication` | 8 | 十八反/十九畏配伍禁忌（安全护栏） |
| | `kg_source` | 13 | 知识出处（防幻觉引用溯源） |

| **养殖管理** | `pig_farms` / `pig_groups` / `pigs` / `users` / `user_group` | 1/3/0/1/0 | 养殖上下文与用户权限 |
| **农户指导** | `farmer_guidance` / `guidance_execution` | 0/0 | 指导建议与执行反馈 |

| | `dashboard_stats` | 1 | 看板统计 |

### 4.2 论治引擎实际使用的表（4 张 + 2 张落库）

```
查询：
  disease               label→中文病名 + 别名归一（辨病纠错比较）
  syndrome_mapping      ⭐ 辨证规则检索（SQL 精确检索，体温区间+关键词）
  syndrome              （JOIN）规则→证候名
  herb                  （JOIN）规则→疾病名（交叉验证）
  herb + herb_contraindication   安全校验（剂量区间/十八反/孕猪）

落库：
  diagnosis_record + prescription_record   （api.py _save_record）
```

**RAG 数据源**（不查 MySQL）：`data/kg/symptom_disease.csv`（辨证库 11 条，与 syndrome_mapping 同源导出）、`data/kg/disease_formula.csv`（论治库，来自 formula+formula_herb+add_rule）、`data/rag/classics/*.txt`（典籍）。

### 4.3 理-法-方-药逻辑链（知识库设计主线）

```
syndrome_mapping(多维体征) → syndrome(证候=理+法) → formula(方)
                                                    └─ formula_herb(药+剂量) + add_rule(随症加减) → herb(药物属性+安全区间)
```

### 4.4 数据流全景

```
用户输入(disease label + symptoms + temp + weight + severity)
  │
  ├─ disease.label → 中文病名（DB）
  ├─ LLM 查询改写 → 检索词
  ├─ CSV 辨证库全量 + 典籍Top5（RAG，文件）
  ├─ syndrome_mapping SQL 检索（DB）+ 规则交叉验证（DB）
  ├─ LLM 辨证 → 证型/治则
  ├─ CSV 论治库全量 + 典籍Top5（RAG，文件）
  ├─ LLM 组方 → 基础方/药材/加减
  ├─ herb + herb_contraindication 安全校验（DB，规则引擎）
  └─ 落库 diagnosis_record + prescription_record（DB）
```
