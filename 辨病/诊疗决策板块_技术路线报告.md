## 一、板块定位与目标

### 1.1 在系统中的位置

诊疗决策板块位于"监测→**诊断→治疗**→评估"闭环的**核心决策层**，承接监测板块（杨宇航/郭悦负责）输出的咳嗽检测结果，完成从"检测到咳嗽"到"诊断出疾病、给出治疗方案"的智能跃迁。

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  监测板块  │───▶│ 诊疗决策板 │───▶│  整合板块  │───▶│  前端展示  │
│ (咳嗽识别) │    │ (本板块)  │    │ (周海斌)  │    │ (小程序)  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
      诊断模型     辨证推理    治疗生成
     (多分类)    (LLM+RAG)   (知识图谱+组方)
```

### 1.2 核心目标

| 维度 | 目标 |
|------|------|
| **诊断** | 基于咳嗽声学特征+多模态数据（体温、精神状态），实现疾病类型多分类，准确率 ≥ 90% |
| **辨证** | 融合中医辨证论治体系（三期分型：邪袭肺卫→疫热壅肺→气阴两伤），实现可解释的病程推理 |
| **治疗** | 基于知识图谱 + LLM 推理，自动生成中药组方建议，包含药材、剂量、用法 |
| **评估** | 建立治疗反馈机制，支持组方调整与疗效追踪 |

## 三、核心技术路线

### 3.1 诊断模型（Diagnosis Model）

#### 3.1.1 问题定义

**输入**：咳嗽声学特征向量 + 多模态辅助特征  
**输出**：疾病类别概率分布 P(disease | features)，疾病类别数 K（猪肺疫、支原体肺炎、猪流感、PRRS等）

#### 3.1.2 特征工程

**声学特征（主特征）**：

| 特征类别 | 具体特征 | 维度 | 来源依据 |
|----------|---------|------|---------|
| MFCC | 13维静态 + Δ + Δ² | 39维 | 纪楠(2023)、付小朋(2025) |
| logFBank | 64维 + Δ + Δ² | 192维 | 王梦雨(2022) |
| 语谱图特征 | LBP + HOG + CNN深度特征 | 变长 | 王锡鹏(2024) |
| 时域特征 | 短时能量、过零率、RMS | 3维 | 纪楠(2023) |
| 频域特征 | 频谱质心、带宽、平坦度、滚降度 | 6维 | 纪楠(2023) |

**多模态辅助特征**：

| 模态 | 特征 | 采集方式 |
|------|------|---------|
| 体温 | 红外测温数值、体温变化趋势 | 红外检测仪 |
| 精神状态 | 活动频率、站卧姿态、长期静止时间 | 摄像头 + 行为识别模型 |
| 环境 | 温湿度、氨气浓度、通风状态 | 环境传感器 |

#### 3.1.3 模型架构

**方案A：多域特征融合 + 集成学习（推荐主方案）**

基于纪楠(2023)的 A-TF 架构 + SSLRB 混合集成：

```
                    ┌─────────────┐
    MFCC特征 ──────▶│             │
    logFBank ──────▶│ 特征拼接融合 │──▶ SVM-Stacking ──▶ LR-Bagging ──▶ 疾病类别
    语谱图深度特征 ─▶│             │      (第一层)        (第二层)
    时频域统计特征 ─▶│             │
                    └─────────────┘
```

- **第一层 SVM-Stacking**：多个不同超参数的 SVM 基分类器（RBF核，C=100, γ∈{0.1, 0.01, 0.001}），3折分层交叉验证生成元特征
- **第二层 LR-Bagging**：M=3 个逻辑回归元学习器 Bagging 集成，配合随机上采样（ROS）处理类别不平衡
- **优势**：在重度不平衡数据集F1仍达 92.19%（纪楠2023），适配猪呼吸道疾病天然分布不均的现实

**方案B：CNN-BiLSTM 多分类（备选方案）**

基于付小朋(2025)的二分类模型扩展为多分类：

```
MFCC特征图 ──▶ Conv2D(32,3×3) ──▶ MaxPool ──▶ Conv2D(64,3×3) ──▶ MaxPool
                                                                      │
                                                                      ▼
                                            Softmax(K类) ◀── Dense ◀── BiLSTM(64) ──▶ BiLSTM(32)
```

- 2层CNN提取局部声学特征 → BiLSTM双向建模时序依赖 → 全连接+Softmax输出K类概率
- 可引入 SENet 注意力机制增强关键频段感知

**方案C：多模态对齐融合（进阶方案）**

```
 声学特征 ──▶ 声学编码器(CNN-BiLSTM) ──▶ ┐
 体温数据 ──▶ 数值编码器(MLP) ────────▶ ├── 跨模态注意力融合 ──▶ 分类头
 行为特征 ──▶ 时序编码器(LSTM) ───────▶ ┘
```

#### 3.1.4 训练策略

| 参数 | 设定 |
|------|------|
| 优化器 | Adam，初始学习率 0.001，余弦退火衰减 |
| 批次大小 | 32-64 |
| 训练轮数 | 50-100，Early Stopping (patience=15) |
| 损失函数 | 交叉熵（可加权处理类别不平衡） |
| 验证策略 | 5折分层交叉验证 |
| 数据增强 | 时间拉伸(0.75-1.25x)、音高偏移、加噪(SNR 5-15dB)、时移 |
| 正则化 | Dropout 0.5、L2权重衰减 1e-4 |

#### 3.1.5 评价指标

- **总体**：Accuracy、Macro-F1、Weighted-F1
- **各类别**：Precision、Recall、F1、混淆矩阵
- **不平衡鲁棒性**：PR-AUC、G-mean
- **Baselines**：单一SVM、RF、XGBoost、CNN、LSTM、BiLSTM、Transformer

### 3.2 辨证推理引擎（Syndrome Differentiation Engine）

#### 3.2.1 设计思路

诊断模型输出疾病类型后，辨证层基于**中医辨证论治理论**进行病程分期和证型判定。本项目的 PPT 三代技术方案已确立三期辨证框架：

```
前期（邪袭肺卫）──▶ 中期（疫热壅肺）──▶ 后期（气阴两伤）
  表证、卫分证        里证、气分证        虚证、气阴亏虚
```

辨证层需要完成：**疾病类型 + 病程阶段 → 证型判定 → 治则治法**

#### 3.2.2 核心技术：Qwen 多智能体推理系统

基于 AI Scientist 论文的多智能体架构，构建四 Agent 协作推理流水线：

```
┌─────────────────────────────────────────────────────────┐
│                 Qwen Multi-Agent Pipeline                 │
│                                                           │
│  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐    │
│  │ 诊断 Agent   │──▶│ 辨证 Agent   │──▶│ 组方 Agent   │    │
│  │ (DxAgent)   │   │ (SxAgent)   │   │ (RxAgent)   │    │
│  │             │   │             │   │             │    │
│  │ 分析声学特征 │   │ 判定证型    │   │ 推荐方剂    │    │
│  │ 结合临床数据 │   │ 分期定位    │   │ 加减化裁    │    │
│  │ 生成鉴别诊断 │   │ 推导治则    │   │ 剂量计算    │    │
│  └─────────────┘   └─────────────┘   └─────────────┘    │
│                          │                                │

│  │  │ 文献库   │ │ 数据库   │ │ (脱敏历史处方)    │  │    │
```

#### 3.2.3 各 Agent 职责与 Prompt 设计

**Diagnosis Agent (DxAgent)**：

```
系统角色：资深兽医诊断专家
输入：咳嗽检测结果（咳嗽频率、时长、强度）+ 体温 + 精神状态 + 环境参数
任务：
  1. 综合分析多模态临床数据
  2. 列出鉴别诊断列表（按概率排序）
  3. 给出关键鉴别依据（咳声特征、伴随症状等）
输出：结构化鉴别诊断报告（JSON）
  {
    "primary_diagnosis": "猪支原体肺炎",
    "differential": [
      {"disease": "猪肺疫", "probability": 0.15, "key_diff": "无高热"},
      {"disease": "PRRS", "probability": 0.08, "key_diff": "无繁殖障碍表现"}
    ],
    "reasoning": "患猪咳嗽声呈干咳、短促、单咳为主，MFCC高频段能量偏低...",
    "confidence": 0.85
  }
```

**Syndrome Agent (SxAgent)**：

```
系统角色：中兽医辨证专家
输入：DxAgent诊断结果 + 病程信息 + 临床表征
任务：
  1. 判定病程分期（前/中/后期）
  2. 确定证型（邪袭肺卫/疫热壅肺/气阴两伤）
  3. 推导治则治法（解表宣肺/清热化痰/益气养阴）
输出：辨证报告（JSON）
  {
    "stage": "中期",
    "syndrome": "疫热壅肺",
    "principle": "清热化痰，宣肺平喘",
    "evidence": ["咳嗽频繁", "痰黄稠", "呼吸急促", "体温升高"],
    "reasoning": "咳声由干咳转为湿咳，痰音明显，伴体温升高..."
  }
```

**Formula Agent (RxAgent)**：

```
系统角色：中兽药师/方剂学专家
输入：SxAgent辨证结果 + 猪只体征参数（体重、月龄、病情严重度）
任务：
  1. 从知识图谱匹配基础方剂
  2. 根据猪只个体差异进行加减化裁
  3. 计算精确剂量（按饲料混饲比例）
输出：处方建议（JSON）
  {
    "base_formula": "麻杏石甘汤加减",
    "herbs": [
      {"name": "麻黄", "dosage_g": 15, "role": "君-宣肺平喘"},
      {"name": "石膏", "dosage_g": 30, "role": "臣-清热泻火"},
      ...
    ],
    "preparation": "按500g饲料混饲",
    "course": "连用5-7天",
    "contraindications": ["孕猪慎用麻黄"],
    "reference": "《中兽医学》第X章 / 临床病例ID-XXX"
  }
```

**Verification Agent (VxAgent)**：

```
系统角色：用药安全审核专家
输入：RxAgent处方 + 药物相互作用数据库
任务：
  1. 检查剂量是否在安全范围
  2. 检查药物配伍禁忌（十八反、十九畏）
  3. 检查猪只特殊状态（孕期、幼龄）禁忌
  4. 标记风险项，通过/否决/修改
输出：审核报告
  {
    "approved": true,
    "warnings": ["麻黄剂量接近上限，建议监测呼吸频率"],
    "modifications": [],
    "safety_score": 0.92
  }
```

#### 3.2.4 RAG 知识库构建

| 知识库 | 内容 | 格式 | 来源 |
|--------|------|------|------|
| 中兽医经典 | 《中兽医学》《兽医中药学》《元亨疗马集》摘要 | 结构化文本 | 教材/专著 |
| 中药药理 | 300+味中药的性味归经、功效、安全剂量、禁忌 | 知识图谱三元组 | 药典/《中药大辞典》 |
| 方剂库 | 经典方剂组成 + 加减化裁规则 + 适应症 | 结构化 JSON | 中兽医学教材 |
| 临床病例库 | 脱敏历史处方 + 疗效追踪 | 向量嵌入 | 合作猪场兽医记录 |
| 疾病知识库 | 猪呼吸道疾病病原、症状、流行病学 | 结构化文本 | 兽医学教材/论文 |

**RAG 检索流程**：
1. 将辨证结果编码为查询向量（使用 Qwen Embedding / text2vec）
2. 在向量数据库中检索 Top-K 相关文献/方剂/病例（使用 Milvus / ChromaDB）
3. 召回的上下文片段注入各 Agent 的 System Prompt
4. Agent 基于检索结果进行推理，引用出处

#### 3.2.5 SFT 微调策略

在推理引擎上线前，对 Qwen 模型进行领域监督微调：

- **基座模型**：Qwen-Max / Qwen-Plus（通过百炼平台）
- **微调数据**：
  - 诊断数据：{咳嗽特征+临床表征} → {疾病诊断+鉴别依据}，目标 200-500 条
  - 辨证数据：{疾病+症状+体征} → {分期+证型+治则}，目标 200-500 条
  - 组方数据：{证型+猪只参数} → {方剂+剂量}，目标 100-300 条
- **数据来源**：
  - 兽医专家人工标注（殷中琼等四川农大兽医专家团队）
  - PPT三代技术中已验证的组方案例（黄芪30g、甘草25g...）
  - 文献提取的经典方剂-证型对
- **微调方式**：LoRA（低秩适配），rank=16, alpha=32
- **评估**：留出20%数据作为测试集，BLEU/ROUGE评估生成质量 + 兽医专家人工评估

### 3.3 治疗方案生成（Treatment Generation）

#### 3.3.1 中药知识图谱构建

基于 PPT 三代技术中已使用的药材（黄芪、甘草、黄芩、茯苓、桔梗、满山红等），构建猪呼吸道疾病中药知识图谱：

```
┌──────────────────────────────────────────────────────┐
│                    中药知识图谱 Schema                  │
├──────────────────────────────────────────────────────┤
│                                                       │
│   疾病 ──[适用]──▶ 证型 ──[主方]──▶ 方剂              │
│    │                │                 │               │
│    │              [分期]             [组成]            │
│    │                │                 │               │
│    ▼                ▼                 ▼               │
│  病原体          病程阶段          中药(药材)          │
│                                      │               │
│                           ┌─────────┼─────────┐      │
│                          [性味]   [归经]    [功效]     │
│                            │        │         │       │
│                            ▼        ▼         ▼       │
│                          寒热    肺/脾/胃  清热/化痰   │
│                          温凉     /心/肝    /止咳...   │
│                                                       │
│  关系类型：                                            │
│  - disease_has_syndrome: 疾病 → 证型                   │
│  - syndrome_has_formula: 证型 → 方剂                   │
│  - formula_contains_herb: 方剂 → 药材                  │
│  - herb_has_property: 药材 → 性味归经                  │
│  - herb_contraindicates: 药材 → 禁忌                   │
│  - herb_interacts_with: 药材 → 配伍关系(相须/相使/相畏) │
└──────────────────────────────────────────────────────┘
```

**技术实现**：

- 图数据库：Neo4j（社区版）或 NebulaGraph
- 数据导入：从结构化JSON/CSV批量导入节点与关系
- 查询接口：Cypher 查询 + Python SDK (py2neo / nebula3-python)
- 前端可视化：ECharts 关系图展示方剂-药材关联

#### 3.3.2 组方生成流水线

```
辨证结果 ──▶ 知识图谱检索 ──▶ 基础方剂匹配 ──▶ LLM加减化裁 ──▶ 剂量计算 ──▶ 安全校验 ──▶ 处方输出
  │              │                  │                │              │            │
  │              ▼                  ▼                ▼              ▼            ▼
  │          Neo4j Cypher      Top-3候选方       Qwen推理      按体重/饲料比   规则引擎
  │          查证型-方剂关系    按匹配度排序    个性化调整      换算剂量        配伍禁忌检查
```

#### 3.3.3 剂量计算模型

基于猪只体重和给药途径的剂量换算：

```
混饲剂量 (g/500g饲料) = 标准剂量 × 体重系数 × 病情系数

体重系数:
  - 保育猪 (5-25kg):   0.7
  - 生长猪 (25-60kg):   1.0  (基准)
  - 育肥猪 (60-100kg):  1.3
  - 母猪 (>100kg):      1.5

病情系数:
  - 轻度 (初期、单咳):  0.8
  - 中度 (中期、连咳):  1.0
  - 重度 (后期、呼吸困难): 1.2
```

## 六、实验设计

### 6.1 诊断模型实验

**数据集**：
- 训练集：已标注咳嗽+疾病标签的声音样本（目标 ≥500条/类）
- 金标准确诊样本 5%-20%（经2名以上兽医独立审核）
- 8:1:1 训练/验证/测试划分，分层抽样保证类别平衡

**Baselines**：

| 方法 | 来源 | 预期性能 |
|------|------|---------|
| SVM (RBF核, MFCC特征) | 谢杰(2023) | ~87% |
| LSTM (MFCC特征) | 谢杰(2023) | ~90% |
| CNN-BiLSTM (MFCC特征) | 付小朋(2025) | ~84% |
| CNN (logFBank特征) | 王梦雨(2022) | ~96% (二分类) |
| MFCC-CNNs (MFCC+差分) | 王梦雨(2022) | ~93% (四分类) |
| A-TF 多域融合 | 纪楠(2023) | ~97% (二分类) |
| **本方案 (A-TF + SSLRB)** | 本文 | **目标 ≥90% (多分类)** |

**Metrics**：
- 总体准确率 (Accuracy)
- 各类别精确率/召回率/F1
- 宏平均F1 (Macro-F1)
- 加权F1 (Weighted-F1)
- 混淆矩阵
- PR-AUC（评估不平衡鲁棒性）

### 6.2 辨证推理实验

**评估维度**：

| 指标 | 方法 | 目标 |
|------|------|------|
| 证型判定准确率 | 与兽医专家标注对比 | ≥85% |
| 分期判定准确率 | 与兽医专家标注对比 | ≥90% |
| 推理逻辑一致性 | 兽医专家评分 (1-5) | ≥4.0 |
| 处方合理率 | 兽医专家审核通过率 | ≥85% |
| 生成引用准确率 | 文献/方剂出处是否真实可查 | 100%（严禁虚构） |

**Baselines**：
- 无RAG的Qwen直接推理
- 未微调的Qwen直接推理
- 基于规则的模板匹配（非LLM方案）

### 6.3 治疗生成实验

**评估指标**：
- 方剂-证型匹配准确率
- 剂量安全范围合规率（目标 100%）
- 配伍禁忌检测召回率（目标 100%）
- 兽医专家对处方质量的 Likert 5级评分

## 七、风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 标注数据不足（多分类标签） | 高 | 诊断模型性能受限 | ①迁移学习（预训练咳嗽识别模型微调）②小样本学习/数据增强 ③主动学习迭代标注 |
| Qwen模型幻觉（虚构文献/方剂） | 中 | 处方安全风险 | ①RAG强制约束引用真实来源 ②VxAgent规则引擎二次校验 ③输出格式约束（JSON Schema） |
| 中药知识结构化困难 | 中 | 知识图谱覆盖不全 | ①优先手动整理核心方剂（20-30首）②逐步扩展 ③利用Qwen辅助文献信息抽取 |
| 百炼API调用延迟/限流 | 低 | 实时性不足 | ①Redis缓存常见诊断结果 ②异步推理+结果轮询 ③本地部署Qwen-Turbo作为降级方案 |
| 团队对中医理论不熟悉 | 高 | 辨证逻辑质量差 | ①与兽医专家团队（殷中琼等）紧密协作 ②专家标注+审核作为微调数据源 ③PPT三代技术已验证的组方作为种子数据 |
