## 一、模块定位与接口契约

### 1.1 在决策板块中的位置

决策板块采用**两层认知模型**：辨病层（轻量多分类，本模块）→ 论治层（LLM+RAG，已完成，见 `therapy_engine.py`）。

```
监测板块(咳嗽检测) ──▶ [辨病层·本模块] 疾病多分类 ──▶ [论治层·已完成] 辨证组方 ──▶ 输出
                            │                              ▲
                            │  disease + confidence         │ disease_conflict 纠错
                            └───────────────────────────────┘
```

### 1.2 与论治层的接口契约（关键）

论治引擎已就绪，辨病模块必须按契约喂数据，否则链路不通：

| 契约字段 | 类型 | 说明 | 论治层消费点 |
|---------|------|------|-------------|
| `disease` | str | 疾病中文名（须过别名归一） | `therapy_engine` 辨病纠错、辨证 Agent |
| `confidence` | float | 模型置信度 | API 落库 `diagnosis_record.confidence` |
| `temp_c` | float | 体温（多模态，可空） | 辨证库 SQL 精确检索 |
| `symptoms` | str | 自动生成的症状描述 | 辨证 Agent 输入 |
| `cough_type` | str | 咳声类型 | 辨证库匹配 |

- **疾病名必须与论治层 `disease` 表别名归一一致**：猪蓝耳病≡猪繁殖与呼吸综合征（`kb_lookup._same_disease`），避免辨病纠错误报
- 论治层已有**辨病纠错兜底**（规则交叉验证 + LLM 独立判断）——辨病模型出错不会直接导致错误处方，但不应依赖此兜底掩盖模型缺陷
- 桥接代码：`诊疗决策板块_实操手册.md` §bridge.py 草稿，本模块落地为正式 `bridge.py`

### 1.3 数据库现状（两库并存，各司其职）

| 库 | 用途 | 本模块相关表 | 说明 |
|----|------|-------------|------|
| `pig_cough`（MySQL 5.7） | **辨病训练数据** | `disease_types` / `diagnosis_records` / `acoustic_features` / `symptom_details` / `multimodal_features` | 198 条已入库，本文主战场 |
| `pig_diag`（MySQL 8.4） | 论治知识库+业务 | `diagnosis_record` / `model_versions` / `agent_logs` | 决策部分产出，辨病推理结果回写处 |

> 决策点：**不合并两库**。辨病数据与论治知识生命周期不同，保持分离；接口层桥接。

## 三、差距分析（现状 vs 目标）

| # | 问题 | 影响 | 对策 |
|---|------|------|------|
| 1 | **样本量小**：病类仅 13~14 条/类（文献目标 ≥500/类） | 模型方差大、易过拟合、评测不可靠 | ①数据增强 ②分层5折CV+固定划分 ③预训练特征迁移 ④持续采集回路 |
| 2 | **类别极不平衡**：normal 54% vs 病类 6.6~7.1% | 准确率虚高、病类召回低 | ①SSLRB+ROS 上采样 ②Macro-F1 为主指标 ③class_weight |
| 3 | **标签可靠度未知**：目录名即标签，无兽医双审、无金标准确诊样本 | 噪声标签污染模型 | ①柴堰颖人工抽审（听辨+文档溯源）②unknown 2 条不入选 ③标签审计表落库 |
| 4 | **特征管线不一致**：库中 84 维均值池化 vs 手册 §2.4 的 142 维（39+ΔΔ²+64+std） | 训练复现口径混乱 | 统一 `features.py`，两种口径并存，84 维为主基线，扩展口径做消融 |
| 5 | **样本时长仅 1s**：可能截断整段咳嗽（正常类 1.027s 已超限） | 特征信息不完整 | ①按 1s 对齐（现状）②后续要求监测板块输出 ≥1.5s 片段 ③时序模型（CNN-BiLSTM）容忍段内多咳 |
| 6 | **第 6 病（猪肺疫）无音频数据** | 推理时可能撞上 OOD | ①softmax 概率阈值 + 低置信度拒答（转 unknown）②论治层辨病纠错兜底 |
| 7 | **Python 3.14 兼容性**：librosa/numba 是否可用未验证（`test（测试草稿）.py` 在测） | 训练环境可能起不来 | ①首日先跑通依赖自测 ②不可用则降级 Python 3.11 虚拟环境 ③特征提取已入库，训练可脱离 librosa |
| 8 | **无评测基线落库**：`model_versions` / `training_datasets` 表空 | 版本追溯缺失 | 训练脚本自动写库（含特征参数哈希） |

## 四、技术路线（定稿）

### 4.1 数据工程

**① 标签审计（先行，1 天）**
- `unknown/` 2 条：人工听辨 → 归入某类或剔除出训练集（建议先剔除，后续作 OOD 测试）
- 各病类抽 3~5 条复听，核对标签与文件名来源（`raw_symptoms` 字段有"人工分类：xxx"记录）
- 产出 `labels_audit.csv`：file_id, label, 复听意见, 是否入训练集

**② 统一特征管线 `features.py`（与库内口径完全一致，可复算）**

```python
# 主基线口径（与 pig_cough 库 84 维一致，直接可复现）
MFCC 13 (均值)  +  logFBank 64 (均值)  +  时域 3 (能量/ZCR/RMS)  +  频域 4 (质心/带宽/平坦度/滚降)  = 84 维
# 扩展口径（消融用，参考手册 §2.4 与文献）
MFCC 13+Δ+Δ² (均值+标准差) + logFBank 64 均值 = 142 维
```

- 参数：`sr=16000`（源 8k 重采样）、`n_fft=2048`、`hop=512`、`duration=1.0s` 截断/零填充
- 产出 `features_train.npz / features_val.npz / features_test.npz`（X, y, file_id 三件套，便于追溯样本）

**③ 数据增强（仅训练集，小样本核心手段）**

| 增强 | 参数 | 依据 |
|------|------|------|
| 时间拉伸 | rate ∈ [0.75, 1.25] | 纪楠(2023) |
| 音高偏移 | ±2 半音 | 王锡鹏(2024) |
| 加噪 | 高斯/粉噪 SNR 5~15dB | 纪楠(2023) |
| 时移 | ±0.2s | 付小朋(2025) |

- 病类样本 ≤50 条 → 每类增强至 ≥60 条（4~5 倍），normal 类不增强（防类间混淆）
- 增强样本**不入库**（防污染真实特征表），仅作训练时动态生成

**④ 数据划分（固定随机种子，保证复现）**

- 8:1:1 分层划分（`random_state=42`，按病类分层）
- 病类仅 13~14 条 → 验证/测试各 1~2 条/类，**5 折分层 CV 为主评估协议**，固定划分仅用于最终报告复现
- 划分清单落库 `training_datasets`（含文件清单 JSON）

### 4.2 模型路线（分阶段递进）

```
Step 0 快速体检 ──▶ Step 1 SVM Baseline ──▶ Step 2 SSLRB 主方案 ──▶ Step 3 CNN-BiLSTM(备选)
  特征有效性            先跑通              小样本+不平衡主力        时序建模能力
                                                    │
                                              Step 4 预训练迁移(可选)
                                              Wav2Vec2.0 / AST 微调
```

| 阶段 | 模型 | 说明 | 通过门槛（5折 Macro-F1） |
|------|------|------|--------------------------|
| Step 0 | LR / RF / SVM 快速体检 | 特征有效性验证，1 小时内出结果 | ≥0.60 继续；<0.60 先查数据问题 |
| Step 1 | SVM RBF（C=100, γ=0.01） | 手册 §3.1 代码就绪，验证集 ≥80% 为经验门槛 | ≥0.65 |
| **Step 2** | **SSLRB（主方案）** | 3 个 SVM 基分类器（γ∈{0.1,0.01,0.001}）3 折分层 CV 生成元特征 → 3 个 LR 元学习器 Bagging + ROS 上采样 | **≥0.72** |
| Step 3 | CNN-BiLSTM | 2 层 CNN + BiLSTM + Softmax，PyTorch；1s×8k 重采样 16k 的 logFBank 图输入 | ≥0.70 |
| Step 4 | Wav2Vec2.0 / AST 微调 | 小样本迁移，样本量 ≥300 时启动 | ≥0.75 |

- Step 0~2 仅依赖已入库 84 维特征（`extract_and_insert` 数据已备好），**不阻塞**；Step 3 起需 librosa 预处理管线
- 每个 Step 产出：模型权重 + 评估报告（5 折均值±std）+ `model_versions` 落库

### 4.3 评估体系

**主指标（不平衡数据下以 F1 为准，accuracy 仅作参考）**：

- Macro-F1（主判据）、各类 Precision/Recall/F1、混淆矩阵
- Accuracy、Weighted-F1、PR-AUC、G-mean（辅助）

**验收分级（小样本现实修正）**：

| 级别 | Macro-F1 | 病类平均召回 | 健康类召回 | 说明 |
|------|----------|-------------|-----------|------|
| 及格（可联调） | ≥0.65 | ≥0.60 | ≥0.90 | 论治层辨病纠错可兜底 |
| **达标（交付）** | **≥0.75** | **≥0.70** | **≥0.95** | 与技术路线"≥90%准确率"目标在小样本下的等价表述 |
| 挑战（数据扩容后） | ≥0.85 | ≥0.80 | ≥0.98 | 需病类样本 ≥100/类 + 迁移学习 |

> 说明：技术路线 §6.1 的"准确率 ≥90%"建立在 ≥500 条/类的大样本前提上；当前 13~14 条/类时 accuracy 会被 normal 类主导虚高，故改用 Macro-F1 为主判据。**数据扩容（监测板块持续采集 + 增强）是冲击 90% 准确率的必要路径**，列为长期任务。

### 4.4 工程落地（与决策部分代码风格一致）

```
辨病/
├── 辨病模块_实施路线文档.md        # 本文
├── features.py                    # 统一特征管线（与库内口径可复算）
├── labels_audit.csv               # 标签审计表
├── train_baseline.py              # Step 1 SVM
├── train_sslr.py                  # Step 2 主方案
├── train_cnn_bilstm.py            # Step 3（备选）
├── predict.py                     # 推理：wav → {disease, confidence, cough_type, symptoms}
├── bridge.py                      # 辨病→论治桥接（disease 别名归一 + 契约组装）
├── test_辨病.py                    # 测试套件（镜像决策部分 test_manual.py 风格）
└── pig_cough_data/                # 标注数据（现有）
```

**推理链路**：

```
wav ──▶ features.py 提取 84 维 ──▶ predict.py 分类 ──▶ bridge.py ──▶ 论治引擎 /api/diagnosis
                                                                    │
                                        disease 中文名 + confidence + symptoms + temp_c
```

- 低置信度处理：`confidence < 0.6` → 结果标 `unknown`（猪肺疫等 OOD 场景），论治层按"缺辨病依据"走辨病纠错
- `bridge.py` 自动生成 `symptoms`（由 `cough_type` + 概率 Top2 疾病的典型症状模板组装），体温/精神字段留空待多模态接入
- 回写：推理结果写 `pig_diag.diagnosis_record`（业务库）+ `pig_cough` 可选镜像，模型版本写 `model_versions`

**测试体系**（镜像决策部分，40 项测试风格）：

| 块 | 内容 |
|----|------|
| 特征复算 | 库中特征 vs `features.py` 复算误差 < 1e-6（随机抽 10 条） |
| 模型加载 | 权重加载、类别数 =5、预测形状正确 |
| 分类正确性 | 已知 5 类各抽 3 条，Top1 命中率 |
| 别名归一 | 猪蓝耳病≡猪繁殖与呼吸综合征 等映射通过 |
| 桥接契约 | bridge 输出 JSON 各字段齐全，论治引擎端到端 5 案例可跑通 |
| 低置信度拒答 | 高斯噪声输入 → unknown 兜底生效 |

### 4.6 数据扩容路径（长期，冲击 90% 目标）

1. **监测板块回接**：猪场持续采集咳嗽片段（要求 ≥1.5s、8k/16k、带时间戳与圈舍号）
2. **主动学习**：模型低置信度样本 → 兽医听辨标注（金标准确诊 5%~20%）
3. **多模态接入**：体温/精神数据入 `multimodal_features` → 方案 C 跨模态融合

## 七、文献依据（与路线报告 §3.1 对齐）

1. **纪楠(2023)**《基于多域特征融合的生猪咳嗽声识别方法研究》：A-TF 多域融合 + SSLRB 混合集成，重度不平衡 F1=92.19%；MFCC/logFBank/时域/频域特征集；时间拉伸/加噪/时移增强 — **主方案来源**
2. **王梦雨(2022)**《基于深度神经网络的猪只咳嗽声识别预警系统设计与实现》：MFCC-CNNs 四分类约 93%、logFBank CNN 二分类约 96% — Step 3 特征图输入参考
3. **付小朋(2025)**《基于CNN-BiLSTM的猪咳嗽声识别方法》：CNN 局部特征 + BiLSTM 时序建模 — Step 3 架构来源
4. **谢杰(2023)**《基于智能语音技术的猪只声音监测研究》：SVM(MFCC) ~87%、LSTM ~90% — Step 0/1 基线预期
5. **王锡鹏(2024)**《复杂环境下基于多分类器融合的猪咳嗽声自动检测方法研究》：多分类器融合 + 语谱图 LBP/HOG 特征 — 增强与特征扩展参考
6. 纪楠论文数据集规模（样本上万条）远超本项目 198 条 — 本路线 §4.6 数据扩容路径的立项依据

## 九、关键决策记录（本模块）

| # | 决策 | 原因 |
|---|------|------|
| 1 | 主评估指标从 Accuracy 改为 **Macro-F1** | normal 占 54%，accuracy 被主导虚高；病类召回才是临床价值 |
| 2 | 主方案沿用 **SSLRB**，SVM 为基线、CNN-BiLSTM 为备选 | 与决策部分技术路线一致；小样本下传统 ML 更稳，深度学习需扩样后发力 |
| 3 | **84 维均值池化特征为主基线** | 与已入库 792 条完全一致，训练零阻塞、可复现；扩展 142 维仅作消融 |
| 4 | unknown 2 条**剔除出训练集** | 标签不可信，宁可少样本不要噪声 |
| 5 | 增强样本**不入库**，仅训练时动态生成 | 防污染真实特征表（acoustic_features 是后续多模态对齐的基准） |
| 6 | 5 折分层 CV 为主协议，固定 8:1:1 仅复现用 | 病类 13 条时单次划分方差太大 |
| 7 | 低置信度拒答转 unknown | 猪肺疫等未训练类别宁可拒答，交给论治层辨病纠错与人工 |
| 8 | 两库分离不合并 | 训练数据（pig_cough）与知识/业务（pig_diag）生命周期不同 |
